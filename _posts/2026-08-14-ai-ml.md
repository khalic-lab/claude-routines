The through-line this cycle is the field auditing its own autonomous-scientist ambitions from both ends at once. On the very days new "AI scientist" systems landed — a 27-billion-parameter agent from the startup Inherent that *outscores* Claude Opus 4.8 and GPT-5.5 at replicating published research — a sober systematic evaluation of seven frontier models concluded that today's research agents behave like "engineering optimizers, not researchers," and a new benchmark asked whether any agent can write real code together with a machine-checked proof that it is correct. A quieter interpretability strand landed a sharper blow: two of the field's standard measuring instruments — sparse-autoencoder ablation scores, and the "does the model know it's being tested" probe — are, on inspection, largely reporting artifacts of how the experiment was wired up rather than facts about the model. If you read three things this cycle, make them **Training AI Scientists to Replicate Research**, **A Probe Direction Is a Property of Its Prompt**, and **MARCH**.

## 📄 ML/AI research (arXiv)

- <a id="st-9c90df4598b6" class="st-a"></a>**A 27B "AI scientist" beats Claude Opus 4.8 and GPT-5.5 at replicating published research** — [arXiv:2608.13331](https://arxiv.org/abs/2608.13331) · D. Falck, S. Sabri, L. Kirsch, E. Hughes et al. (Inherent) · [inherentlabs.ai](https://inherentlabs.ai/) `[new source]` · `[preprint]`

  Replication — taking a published paper and reproducing its results from scratch — is harder than it sounds, because papers routinely leave methodological details unstated, so a faithful redo demands the same open-ended, hypothesis-driven work as original research. The authors build **Replica**, a large task space of replication challenges, and an auto-generated *rubric-based judge* (a checklist grader) that they show is low-noise and agrees with human assessments of replication quality. Using that as a reward signal, they post-train **Faraday**, a 27B agent that calls coding agents as tools.

  **Why it matters:** on held-out replication tasks Faraday reportedly surpasses Claude Opus 4.8 and GPT-5.5 — a small, purpose-trained model beating two frontier systems at a concrete scientific-labor task, not a toy benchmark. Treat the head-to-head numbers as the authors' own until reproduced, but the result is a real data point in the "how close are autonomous researchers" debate. _Submitted 2026-08-14._

- <a id="st-183973b8f6bc" class="st-a"></a>**A hard look at research agents finds optimizers, not scientists** — [arXiv:2608.13417](https://arxiv.org/abs/2608.13417) · Y. Li, W. Yang, H. Tan et al. (Meituan; University of Chinese Academy of Sciences) · `[preprint]`

  Most agent evaluations report only a final score, which hides *where* an agent gained or lost ground and whether it actually learned from earlier attempts. This study runs seven frontier models across 36 long-horizon R&D tasks under a framework that scores the *process* — how an agent frames a solution, executes it, and responds to feedback — and separately tests whether experience from one run improves later ones.

  **Why it matters:** the verdict is a useful cold shower: current agents "operate more like engineering optimizers than fully autonomous researchers" — good at grinding a well-posed objective, weak at the reuse-of-experience that defines a scientist. Read against the Faraday result above, the two papers frame the live disagreement about how far this capability really extends. _Submitted 2026-08-13._

- <a id="st-2a59c69eaae6" class="st-a"></a>**A benchmark asks whether agents can write code *and* prove it correct** — [arXiv:2608.13522](https://arxiv.org/abs/2608.13522) · H. Lou, Y. Sun, P. Song, D. Song et al. (UC Berkeley; University of Chicago; Caltech +3 more) · `[preprint]`

  AI coding agents give no guarantee their output is correct. *Verified code generation* raises the bar: the agent must emit both an implementation and a machine-checked proof that the code meets a formal specification (a proof assistant mechanically confirms it, leaving no room for a plausible-but-wrong answer). Prior benchmarks tested single functions, or proofs against code someone else wrote. **Vero** is the first to test both together at the whole-*repository* level — 43 multi-module instances drawn from real projects across Python, Dafny, Verus, and Coq.

  **Why it matters:** "the agent wrote it and the tests pass" is a weak guarantee; "the agent wrote it and a proof checker verified it against a spec" is a strong one. A repository-scale benchmark is what tells us whether that stronger guarantee is within reach for real codebases rather than isolated snippets. _Submitted 2026-08-13._

- <a id="st-0d70d77aa41b" class="st-a"></a>**A popular "is the model aware it's being tested" probe turns out to measure the prompt, not the model** — [arXiv:2608.13329](https://arxiv.org/abs/2608.13329) · V. Noël (Devoteam) · `[preprint]`

  A model that acts differently when it senses an evaluation would quietly corrupt the evals we trust, so researchers have tried to read that "sense" straight from activations: contrast the model's internal state on prompts that *announce* a test against prompts that don't, extract the difference as a direction, and report how cleanly it separates held-out cases — then compare that score across models and correlate it with scale. The catch, the author shows, is that "a prompt that announces an evaluation" is not one prompt but a *choice among many*, and the method never pins down which.

  **Why it matters:** holding the task fixed and varying only that unstated choice, both the headline score *and even the direction in which it trends with model size* follow the prompt rather than the model. It's a clean warning that a widely cited interpretability result may be an artifact of prompt selection — exactly the kind of honest self-check the safety-eval literature needs. _Submitted 2026-08-13._

- <a id="st-5e088c03cff8" class="st-a"></a>**The standard way to score a sparse autoencoder lets the dictionary grade its own exam** — [arXiv:2608.13337](https://arxiv.org/abs/2608.13337) · V. Noël (Devoteam) · `[preprint]`

  Sparse autoencoders (SAEs) try to name the concepts a model computes; the usual test of whether a discovered feature *matters* is to switch it off and see what changes. But a feature fires at many tokens, and the effect must be read at one of them — and the convention (measure where the feature fires hardest) means the *dictionary being evaluated* picks the measurement point. Take two SAEs Google released for the same model, match their features by similarity, and even near-identical features get measured at different tokens.

  **Why it matters:** two dictionaries "compared" under the standard protocol are often not being measured on the same footing at all, so leaderboard-style SAE comparisons can reward measurement choices rather than better features. It's a distinct paper from the earlier "which SAE you trained decides causality" line, but it points the same way: interpretability's evaluation plumbing needs auditing before its scores can be trusted. _Submitted 2026-08-13._

- <a id="st-8560880a9d3c" class="st-a"></a>**A recurrent memory that routes by content keeps long-range recall without a growing cache** — [arXiv:2608.12435](https://arxiv.org/abs/2608.12435) · M. Zhang, K. Yang, N. Ding, B. Zhou et al. (Shanghai AI Laboratory; Tsinghua University; Fudan University) · `[preprint]`

  Transformers recall far-back tokens well because they keep a per-token memory (the KV cache) that grows with the input — but that means quadratic training cost and a cache that swells linearly at inference. Recurrent models fix the cost by squeezing all history into a fixed-size state, but they forget: new updates overwrite old associations, so only recent context survives. **MARCH** (Memory-Anchor Routing across Context History) adds *content-routed state anchors* — a fixed set of memory slots that incoming information is routed to by what it's about, so older associations are preserved in the slot they belong to rather than being overwritten.

  **Why it matters:** the long-context/recurrent trade-off — cheap decoding versus reliable recall — is one of the central architectural tensions in scaling, and a fixed-size state that stops forgetting is a genuine attempt to get both. From a top Chinese lab consortium, it's worth watching whether the recall gains hold on the hardest retrieval tasks. _Submitted 2026-08-12._

- <a id="st-ceac7caf792d" class="st-a"></a>**Tree-shaped speculative decoding lets diffusion drafters propose several futures at once** — [arXiv:2608.13524](https://arxiv.org/abs/2608.13524) · T. Li, Y. Luo, X. Shang, Z. Shen (affiliation not listed) · `[preprint]`

  Speculative decoding speeds up text generation losslessly: a fast "drafter" guesses several tokens ahead and the real model verifies them in parallel. Diffusion drafters can propose a whole block at once, but their guesses aren't conditioned on which earlier draft tokens were actually chosen, so accuracy suffers. **DARTree** is a training-free method that extends a pretrained autoregressive correction head from a single draft *chain* to a *tree*: it builds a fixed-width candidate tree, scores all nodes at each depth in one batch, then applies correction along the best-fitting branch.

  **Why it matters:** speculative decoding is one of the most practical inference speedups in deployment, and combining diffusion's parallel proposals with tree-structured verification is a concrete way to widen the guess without losing the causal correction that keeps it accurate. _Submitted 2026-08-13._

- <a id="st-ad6388245d56" class="st-a"></a>**You can skip parts of an LLM's matrix multiplies at inference, no retraining** — [arXiv:2608.13426](https://arxiv.org/abs/2608.13426) · Z. Lan, Y. Li, J. Zhou (University of Chicago; Stony Brook University) · `[preprint]`

  Most of a transformer's inference cost is repeated large matrix multiplications. **Reduced Matrix Multiplication (RMM)** is a training-free, input-adaptive trick: for each product it keeps only the most *informative slices* along the shared "contraction" dimension (the axis summed over when multiplying two matrices), discarding the rest, controlled by a single retention-ratio knob that trades accuracy for speed smoothly and predictably. Weights are untouched.

  **Why it matters:** across models from 1B to 70B, how much you can cut depends on family, task, and component — but tolerance often *grows* with scale, and under moderate reduction accuracy holds across generation and long-context settings. A drop-in lever with a predictable dial is exactly what practitioners can actually use. _Submitted 2026-08-13._

- <a id="st-498dd69866d6" class="st-a"></a>**A single symmetry explains why networks learn in sudden jumps yet obey smooth scaling laws** — [arXiv:2608.13335](https://arxiv.org/abs/2608.13335) · L. Ziyin, Y. Xu, T. Poggio, I. Chuang (MIT; EPFL) · `[preprint]`

  Two puzzling training behaviors coexist: the loss can sit on a long plateau and then drop *abruptly* (learning in steps), while at the same time training curves follow *smooth* power laws (scaling laws) — and both appear in wildly different architectures, hinting that a few "collective variables" govern the dynamics regardless of the microscopic details. The authors show a symmetry fixes those variables: a layer is a sum over interchangeable units, so relabeling units changes nothing; that permutation symmetry, plus smoothness, forces a universal leading form near the small initial weights — a quadratic Tr[WWᵀA(x)] in which every architectural detail is packed into one "structure matrix" A(x).

  **Why it matters:** if a single minimal model reproduces both sudden learning and smooth scaling from symmetry alone, it's a rare piece of *theory that unifies* two empirical mysteries deep learning has mostly just catalogued — the kind of result that can eventually make scaling behavior predictable rather than measured after the fact. _Submitted 2026-08-13._

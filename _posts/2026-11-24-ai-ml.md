## 📄 ML/AI research (arXiv)

This window's strongest papers make one point: the checks used to supervise automated systems can be predictably wrong. Judges reward junk, tests reject correct fixes, confidence numbers never drop, and guards inspect a different tool call from the one that runs. Three are worth reading in full. The Columbia reward-hacking study predicts which loophole a policy will exploit before training starts. The SWE-Gym audit shows how much "unsolved" coding data is really mislabelled. The tool-call smuggling paper shows how JSON parsing differences defeat agent guardrails.

- <a id="st-7749d2706be9" class="st-a"></a>**The first loophole an RL policy exploits in an LLM judge can be predicted before training** — [arXiv:2611.29651](https://arxiv.org/abs/2611.29651) · X. Lyu, Y. Zhao, Q. Qin (Columbia University) · `[preprint]`

  When a model is trained by reinforcement learning against an LLM judge (another model that scores its answers), it can learn to produce degenerate outputs the judge wrongly accepts, such as a lone "{" or the string "Thought process:". This is called reward hacking. The authors define each pattern's "exposure" as how often the starting policy already produces it multiplied by the judge's false-positive rate. Across 36 GRPO runs (GRPO is a common RL fine-tuning method that scores each answer against a group of samples) with seven judges, the most-exposed pattern was the first one exploited in all 12 runs where exploitation happened. False-positive rate alone got it right in only 6.

  **Why it matters:** labs could check a judge for its likeliest loopholes before spending compute on a run, rather than finding the hack afterwards. The evidence is causal (patterns were seeded at controlled doses) but comes from one lab's judges and tasks. _Submitted 22 Nov 2026._

- <a id="st-f947e98782c0" class="st-a"></a>**A quarter of "unsolvable" coding-agent training tasks turn out to be mislabelled** — [arXiv:2611.30207](https://arxiv.org/abs/2611.30207) · Y. Zhang, M. Xu, Y. Zhang et al. (AMD; University of Michigan; Tulane University +4 more) · `[preprint]`

  Coding agents are trained with RL on tasks where hidden tests decide the reward, but those tests are usually checked only against one reference fix. The authors audited SWE-Gym, counting a suspected error only if running the code reproduced it. Among tasks a 9B base model never solves, 74% have a test that rejects correct fixes (a false negative). The rate is 20% among tasks it sometimes solves. About a quarter of all passing patches are actually wrong (false positives). At matched size and difficulty, models trained on the repaired tasks scored 2.4 and 2.7 points higher on held-out SWE-bench Verified and SWE-bench Pro. Simply dropping the never-solved tasks gave no such gain.

  **Why it matters:** a pass rate shows whether a task gives reward, not whether that reward is correct. The released SWE-Gym-Verified (1,087 audited tasks with executed evidence) is a direct fix for anyone training coding agents. _Submitted 23 Nov 2026._

- <a id="st-417928c0a8e8" class="st-a"></a>**Guards and executors can read the same tool call differently, and attackers can exploit the gap** — [arXiv:2611.30624](https://arxiv.org/abs/2611.30624) · I. Santos-Grueiro, D. Romero-Ruiz (Universidad Internacional de La Rioja; Proeduca Summa) · `[preprint]`

  An agent's tool call is a block of JSON that gets parsed several times: by the provider, gateways, SDKs, a safety guard and finally the executor. JSON leaves some choices open, such as which copy of a repeated key counts. So the guard can approve one call while the executor runs another, and the audit log records only the approved one. The authors call this "tool-call smuggling". Across 17 parser configurations most pairs disagree on some inputs, including two official MCP (Model Context Protocol) SDKs. On τ-bench and AgentDojo tasks, an attacker who can rewrite bytes in transit cancelled another customer's reservation. The fix the authors propose is to parse once, keep only the approved schema's fields and seal the call with its ID. It stopped all 7,412 crafted inputs.

  **Why it matters:** many agent guardrails assume the call they inspect is the call that runs. This paper shows that assumption fails in common stacks and gives a concrete fix. _Submitted 23 Nov 2026._

- <a id="st-6e3f1dcfc0ba" class="st-a"></a>**When a tool returns partial data, agents often build a confident wrong answer on it** — [arXiv:2611.28341](https://arxiv.org/abs/2611.28341) · G. Kaynar, B. Yan, C. Kingsford (Carnegie Mellon University) · `[preprint]`

  The authors injected 9 kinds of tool faults into a realistic sandbox (real filesystem, SQLite, local HTTP server) across 30 multi-step tasks. Over 2,100 faulted runs with four agents, correct recovery ranged from 19% to 68%, and 6–26% of runs ended with a wrong answer stated as fact. The fault type mattered more than the model. Faults that return partial data led to fabrication in up to 38% of runs, while outright denials led to honest failure. A monitor that checks answers against structured tool outputs raised correct recovery from 45.6% to 56.3% and cut fabrication from 17.3% to 10.8%.

  **Why it matters:** for anyone deploying agents, the dangerous failure is the plausible half-answer, not the error message, and a cheap checking layer measurably reduces it. _Submitted 20 Nov 2026._

- <a id="st-cf2048ffa21c" class="st-a"></a>**Models' stated step-by-step confidence doesn't drop when they make a mistake** — [arXiv:2611.31228](https://arxiv.org/abs/2611.31228) · D. Theron (affiliation not listed) · `[preprint]`

  A popular agent technique asks models to print a numeric confidence after each reasoning step, so that low confidence triggers backtracking. Across 15,200 math attempts by Qwen2.5-7B, Llama-3.1-8B, Mistral-7B and Phi-4, the author isolated 2,017 errors. The printed confidence did not distinguish wrong steps from sound ones (AUROC, a 0.5-is-chance ranking score, of 0.500–0.561). It stayed at 95–99.9% even at the first error. Injecting a low-confidence tag at the error step raised later corrections by 3.7 to 22.5 points. Injecting it on correct steps cut solve rates by up to 22.8 points.

  **Why it matters:** the generated confidence text responds when doubt is supplied from outside, but it does not reliably flag the model's own errors. Self-correction schemes that rely on it are limited by error detection, not repair. Only small open models were tested. _Submitted 23 Nov 2026._

- <a id="st-88179e8bf9c7" class="st-a"></a>**A frontier model put its odds on 87 open conjectures at 62%; it resolved 10%** — [arXiv:2611.28827](https://arxiv.org/abs/2611.28827) · A. Khaitan, L. Fowl, T. Ortega, A. Kontorovich, S. Arora et al. (Princeton University; Rutgers University) · `[preprint]`

  The authors prompted ChatGPT 5.6 Sol Ultra to pick open problems in geometric analysis (the study of curved spaces using calculus and differential equations) that it rated as at least 50% likely to be settled, and to output a success probability for each. After an audit removed 13, the model attempted 87. Its mean stated probability was 0.617 against an observed resolution rate of 0.103 (Brier score 0.351, where lower is better). The ranking still carried signal (AUROC 0.714): problems it scored higher were resolved more often. All proofs were formalised in Lean, a proof checker that verifies each logical step mechanically.

  **Why it matters:** this is a useful counterweight to this month's maths headlines. The model really did resolve some open problems, with machine-checked proofs, but its own probability estimates were badly inflated. The authors call these exploratory campaign outcomes, not fixed-budget success rates. _Submitted 21 Nov 2026._

- <a id="st-b7374435f69b" class="st-a"></a>**Hazardous actions roughly triple when the same models move from chat to controlling a robot** — [arXiv:2611.30957](https://arxiv.org/abs/2611.30957) · B. Alt (Convergent Robotics) · `[preprint]`

  SayDo pairs eleven benign lab and household instructions with a hazard hidden in the scene. Each runs in six settings, from chat questions about an imaginary robot to closed-loop control of a simulated arm. Across six vision-language models and 11,480 episodes, hazardous-action rates rose from 14% in chat to 47% in the simulator. For the most affected model they went from 2% to 80%, and the rise came mostly from open-weight models. In 73% of unsafe episodes the model's output named the hazard before carrying out the action anyway.

  **Why it matters:** safety scores measured in text did not predict behaviour once the same model controlled a robot, so evaluations need to run in the setting where the model is deployed. This is a single-author benchmark in simulation only. _Submitted 23 Nov 2026._

- <a id="st-65245be5dcbd" class="st-a"></a>**A Hopper-native kernel makes a 4-bit KV cache faster than FP8 in vLLM** — [arXiv:2611.30027](https://arxiv.org/abs/2611.30027) · J. Zhang (Northeastern University) · `[preprint]`

  The KV cache (stored attention keys and values for past tokens) limits how many requests a GPU can serve. A 4-bit cache reads half the bytes of FP8, but H100/H200 "Hopper" GPUs lack FP4 hardware, and vLLM's existing 4-bit paths reach only 10–20% of memory bandwidth, up to 1.7× slower than FP8. The new kernel overlaps loading and decoding and lays out the cache so values feed the tensor cores directly. It reaches 67–75% of peak bandwidth and decodes 1.12–1.64× faster per step than vLLM's FP8 path on Llama-3.1-8B, while holding 1.63× as many tokens.

  **Why it matters:** this means more concurrent long-context requests per GPU with no measured accuracy loss on 7B–32B models, on hardware most operators already run. Prefill-heavy traffic gets about 7% slower. _Submitted 23 Nov 2026._

- <a id="st-3e726c5e7132" class="st-a"></a>**An advisory LLM-agent system helps engineers investigate anomalies at Switzerland's Beznau reactor** — [arXiv:2611.27556](https://arxiv.org/abs/2611.27556) · W. Zhou, L. Baldo, E. Kolbe, M. Arias Chao (ZHAW; University of Basel; TU Delft) · `[preprint]`

  Beznau Unit 1 in canton Aargau, running since 1969, is the world's longest-operating reactor still in service. Its alarm logs, variable catalogues, technical specifications and reports sit in separate systems. The authors built an assistant in which an orchestrating agent splits an engineer's question across sub-agents, each with read-only access to one source. Engineers write the domain procedures in plain language, every answer cites its sources, and the system is strictly advisory.

  **Why it matters:** this is a rare documented deployment of agentic AI in Swiss safety-critical infrastructure. Its design choices (read-only access, traceable answers, no operational authority) are a template for regulated settings. It is a case study, not an evaluation. _Submitted 20 Nov 2026._

## 🏢 Lab blogs & official releases

- <a id="st-bd545a438b27" class="st-a"></a>**OpenAI's chief scientist proposes shared industry limits based on perplexity** — [OpenAI, "Perplexity and Intelligence", 22 Nov 2026](https://openai.com/index/perplexity-and-intelligence) · `[vendor PR]`

  Jakub Pachocki published OpenAI's internal pretraining loss for the first time, measured on its held-out evaluation set. Perplexity is a measure of how well a model predicts the next token. By his figures, GPT-3.5 sat at a log-perplexity of about 0.99, GPT-4 at about 0.91, and models below 0.8 brought "transformative capabilities" in cybersecurity and mathematics. He says a model at about 0.76 began producing research-level maths results, and he expects further jumps in capability in a "~0.68–0.7" window. He proposes that frontier developers agree on common limits, based on perplexity and other measures, that they would not cross until monitoring reaches a concrete milestone, such as "a successor to CoT monitors". He concedes the metric's weaknesses, including incomparable datasets across labs.

  **Why it matters:** this is a frontier-lab executive proposing a measurable pause condition and backing it with internal data. The figures are self-reported on a private dataset that no one outside OpenAI can check, and the post commits OpenAI to no limit of its own.

- <a id="st-a55680e1cb8a" class="st-a"></a>**Anthropic's Claude Ship lets Claude approve pull requests under a team-written policy** — [Claude, "Introducing Claude Ship", 23 Nov 2026](https://claude.com/resources/articles/introducing-claude-ship) · `[vendor PR]`

  Claude Ship combines the existing Code Review product with two agents in beta. PR Steward responds to failing CI, merge conflicts and review comments, and is designed never to approve or merge. Claude Approvals approves routine changes when a policy file in the repository allows it, and sends other changes to a human. Anthropic says that on its Claude Code team, merged PRs more than doubled from June to September while the share reverted fell by more than 40%. That is a single internal team, with no external comparison.

  **Why it matters:** this moves approval itself, not just review, to software running under rules the customer writes. Whether a policy file is enough control is the question for adopters.

- <a id="st-875060338ff1" class="st-a"></a>**DeepMind used Gemini agent teams and Lean proofs to cut quantum-algorithm costs by up to 11.8×** — [Google DeepMind, 23 Nov 2026](https://deepmind.google/blog/finding-faster-quantum-algorithms-with-agents-and-formal-verification/) · paper [arXiv:2611.09822](https://arxiv.org/abs/2611.09822) · `[vendor PR]`

  Separate teams of Gemini 4 agents proposed improvements to known quantum circuits, and each result had to be proved correct in Lean before it counted. That matters because circuits this large can't be tested on today's hardware. Reported gains include 11.8× lower cost for an inertial-confinement fusion calculation, 2.5× for the drug-metabolising enzyme Cytochrome P450, and 290× for a common arcsin routine. DeepMind is releasing the Lean library and verified solutions.

  **Why it matters:** formal proof makes these claims checkable rather than taken on trust. DeepMind itself notes the improved algorithms still exceed what the first error-corrected machines are likely to support.

## 🚀 New models, datasets, & open weights

- <a id="st-a4f31a72ec57" class="st-a"></a>**Thinking Machines releases Inkling 2 Mini, a looped open model that fits in 32 GB** — [Hugging Face blog, 20 Nov 2026](https://huggingface.co/blog/inkling2mini) · `[vendor PR]`

  Inkling 2 Mini is an Apache-2.0 multimodal mixture-of-experts model (each token uses only a few specialist sub-networks) with about 26B total and 3B active parameters and a 1M-token context. Its 12 middle layers run three times per token, so 24 physical layers act like 48. It ships NVFP4/MXFP8 weights with day-one Transformers, llama.cpp, MLX and SGLang support. The 4-bit GGUF fits in 32 GB of unified memory. Hugging Face's own tests put it "at least comparable" to Qwen 3.8 27B, and they say "more validation is needed". It is a distinct model from the much larger Inkling 2 Small that Thinking Machines opened on 14 November.

  **Why it matters:** this is a capable open model sized for a 32 GB Mac, and one of two looped-transformer launches in four days.

- <a id="st-1df490d6252d" class="st-a"></a>**llama.cpp adds NVFP4 support to its Metal backend for Macs** — [ggml-org/llama.cpp PR #32825 (release b12672), 23 Nov 2026](https://github.com/ggml-org/llama.cpp/pull/32825)

  The change adds NVFP4 dequantisation, matrix-vector and matrix-multiply kernels to the Metal backend, so models can run in Nvidia's 4-bit floating-point format on Apple GPUs. It was tested on an M5 Max with Nemotron 3.5 Lightning 30B-A3B.
